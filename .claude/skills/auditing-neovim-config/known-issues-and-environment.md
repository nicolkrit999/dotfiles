## 2. REAL BUGS found late, with root-cause PATTERNS to re-check

Each pattern below caused a real bug that earlier green automated gates did NOT catch. Re-check the whole pattern, not just the instance.

1. **Lazy-loaded plugin needed by a SEPARATE process / headless nvim (vimtex inverse search)**. vimtex was `ft = "tex"`/lazy; the zathura Ctrl+click spawns a fresh headless `nvim --headless -c VimtexInverseSearch ...` that never opens a `.tex` file, so `:VimtexInverseSearch` did not exist and the click did nothing (compile + auto-update worked, masking it). Fix: `lazy = false` for vimtex (commit 2280f92), verified end to end (callback reached line/col). PATTERN: any plugin/command invoked from outside the running editor (viewer callbacks, `nvim --server --remote-*`, `--headless -c`, git hooks, `$EDITOR` use, `firenvim`) must be loadable without its filetype/event/cmd trigger. Grep specs for `ft=`/`event=`/`cmd=` on plugins whose commands are called by external tools (servername files like `/tmp/vimtexserver.txt`, RPC).
2. **Plugin dimming defeats UI that relies on highlight contrast (vimade vs nvim-tree window picker)**. The window-picker letters were invisible because vimade dimmed the inactive windows' statuslines/floats. Fix: a custom window picker (bright letters A/B, "Pick window:") that PAUSES vimade while picking and resumes after. PATTERN: any overlay/picker/float that draws into other windows must be tested with vimade (and other dimming/blend plugins) active; test through real keys in tmux, not headless.
3. **`sync_root_with_cwd` (nvim-tree) was false**: the tree kept the first folder after `:cd`/`:tcd`/`:Z`/`:z`. Fix: `true`. Rules: `nvim` / `nvim .` = start folder, `nvim <dir>` = that dir, later `:cd/:tcd/:Z/:z` move the root. PATTERN: tree/explorer/outline plugins and their cwd synchronisation options; check `update_focused_file`, `sync_root_with_cwd`, `respect_buf_cwd` against the documented behaviour in the guide.
4. **`<Space>Q` counted the fidget.nvim buffer** as an unsaved/open buffer (Yes/No quit question was wrong). Fix: ignore non-file/special buffers (and it now asks Yes/No, default No). PATTERN: any "count/iterate buffers" logic must filter by `buftype`, `buflisted` and plugin UI filetypes (fidget, notify, aerial, NvimTree, dashboard, claude terminal, qf).
5. **F9 collision with nvim-gdb eval**. nvim-gdb maps F4/F5/F8/F9/F10/F11/F12 in the buffer during a pdb session and, when the session ended, left our `<F9>` run key removed ("F9 survives pdb sessions" text in the guide). Fix: `vim.g.nvimgdb_config_override = { key_eval = "<space>dv" }`, python-buffer leader keys `<Space>dc dn ds df dB du`, and a function-key-free alias `<Space>rf` for the `<F9>` run. PATTERN: plugin-owned buffer-local maps that clobber user maps; check `maparg` after the plugin's session ends. Also the user's keyboard has NO function keys, Insert, Page Up/Down or numpad: every function must have a non-F-key way.
6. **Resize left unequal windows**. `VimResized` handler set Claude panel width to 30% AFTER `wincmd =`, so code windows differed by about 4 columns. Fix: set + pin Claude width (`winfixwidth`) first, then `wincmd =`, then restore the pin (code windows equal +-1, Claude exactly 30%). PATTERN: order of layout operations with `winfixwidth/winfixheight` panels; test with 2-3 code windows plus the Claude panel after a terminal resize.
7. **auto-save focus/trigger drift**. Replacing Pocco81 with the okuuva fork silently changed triggers (InsertLeave/TextChanged vs BufLeave/FocusLost) and debounce (fork default 1000 ms); the first commit message wrongly said "same behaviour". Resolved by user decision: BufLeave/FocusLost only. PATTERN: when swapping a plugin for a fork, diff option defaults and trigger events, not just the setup call; commit messages claiming "same behaviour" must be proven.
8. **`:Lazy sync`-style operations rewrite the gitignored `lazy-lock.json` inside the config dir**. A test with fake tools clobbered it down to 2 entries; a test with an empty data dir downloaded 61 MB of nvim-java bundles and silently ran only half the tree-sitter tests; a fake git repo with an https remote caused real credential popups for the user. PATTERN/RULES: tests that touch plugins go through `scripts/isolated-nvim.sh` only; fake repos use local-path remotes with `GIT_TERMINAL_PROMPT=0 GIT_ASKPASS=true`; never use the user's clipboard (one verifier overwrote the Wayland clipboard); scratch only in the harness scratchpad or `$AUDIT_OUT`, never ad-hoc `/tmp` paths (RAM tmpfs 4 GB once hit 99%).
9. **Plugin spec "options" that are dead because a custom `config` function calls setup itself** (nvim-ufo `opts` removed after review). PATTERN: when a spec has both `opts` and `config = function`, the opts are ignored unless config forwards them.
10. **Highlight overrides lost after `:colorscheme`** (nvim-cmp CmpItemAbbrMatch, hop not applied on first load). PATTERN: every `nvim_set_hl` override must be a function called once AND from a `ColorScheme` autocmd in a cleared augroup (0.12: use `{update = true}`).
11. **Gating by env vars instead of tool availability** (rejected design): detection of devShells must be `vim.fn.executable()` at buffer/ftplugin setup or `LspAttach`, never `IN_NIX_SHELL`/`DIRENV_*`, so the same filetype gives the same keys on a non-nix host. Missing tool = silence or ONE short warning, never a stack trace, never a fall-through to a plain Vim key.
12. **Missing `return` after an error echo** (C++ `<F9>`: `echoerr` does not abort, so E121/E116 + empty split), **unconditional ftplugin maps for plugin-owned commands** (typst `<leader>tw` -> E492), **global Java maps whose commands exist only after jdtls attaches** (-> buffer-local on `LspAttach`, `LspDetach` removes them). PATTERN: for every keymap, ask "what happens when the target command/tool is absent?"
13. **`:terminal` via cmdline expansion** (`vsplit | terminal <cmd>`) broke on `%`, `#`, `!` in file paths (E194). Fix: `vim.cmd.vnew(); vim.fn.jobstart(cmd, { term = true })` plus shell escaping and absolute binary paths. PATTERN: never build Ex command strings from file names.
14. **Other recurring-finding families from the gates**: buffer-local vs global shadowing (Select-mode leaks: use `x` not `v` for visual maps), prefix waits, duplicate keymap definitions, dead maps (`<Space>dE`), after/ftplugin options leaking globally (`set`/`vim.o` instead of `setlocal`/`vim.opt_local`), TermOpen turning off numbers for the whole window, `norm` abbreviation rewriting the word anywhere, typos_lsp / ltex flooding `lsp.log` or attaching to bigfile/dashboard/`buftype ~= ""` buffers, bigfile (Snacks) keeping LSP but skipping syntax when the longest line is large.

Harness bugs (false positives, already fixed, do not chase): `vim/fs: Invalid buffer id` traceback when `%bwipeout!` ran before LSP start finished; nvim-notify history empty when the capture ran too early; `checkhealth` under `silent!`; headless runs reporting tiny counts (a wrong report once claimed 207 mappings where 739 exist: always compare counts with a known number; smart_comment suite must be >= 10073 cases, verify.sh exits 3 below 10000).

## 3. ENVIRONMENT

**Neovim**: v0.12.x (0.12.5 from nixpkgs-unstable via the nix repo, `pkgs-unstable.neovim-unwrapped`; nixos-26.05 stable only had 0.12.4). Uses native `vim.lsp.config()/enable()`, `vim.uv`, `vim.diagnostic.config` signs, builtin 0.12 `undotree`, `:restart`. No deprecated APIs in user code (grep was clean). `vim.validate{}` table form is only used by nvim-dbee (upstream).

**Plugin manager**: lazy.nvim bootstrapped in `lua/plugin_specs.lua`, ~115 plugins; `lazy-lock.json` is gitignored and local. nvim-treesitter is the `main` branch (new `require("nvim-treesitter").install/setup` API, `vim.treesitter.start` on FileType via pcall).

**Deployment**: nix home-manager symlinks via `ext-dotfiles.nix` in the nix repo (`users/<user>/{nixos,darwin}/services/`): `".config/nvim" = "general/general-nvim/.config/nvim"`. Switching git branches in the dotfiles checkout changes the live editor instantly; leave the checkout on `develop` when finished.

**Nix providers** (the nix repo is `~/nix`; template location: `~/nix/templates/<user>/dev-environments/language-specific/<lang>/flake.nix`, plus `language-combined/...`):
- Global, in `users/<user>/common/programs/cli-programs/neovim.nix` (`extraPackages`, so on nvim's PATH but NOT necessarily the interactive shell's PATH): ripgrep, fd, fzf, universal-ctags (fzf-lua `<Space>ft` btags; no parser for `.nix` so 0/0 there is expected), wl-clipboard (Linux), bash-language-server, lua-language-server, nixd + nixpkgs-fmt, yaml-language-server, marksman, pyright, typos-lsp, ltex-ls-plus (binary `ltex-ls-plus`), stylua, prettier, `python3Packages.pylatexenc` (provides `latex2text` for render-markdown), `nodejs_latest` (home.packages), `withPython3 = true` (UltiSnips needs pynvim). Treesitter parsers: `nvim-treesitter.withPlugins` (48+4 grammars incl. diff/gitcommit/git_config/git_rebase) land in `~/.local/share/nvim/site/pack/hm`, appended to rtp, so two nvim-treesitter copies exist (lazy's wins; nix's supplies parsers). The wrapper exports `SNACKS_SQLITE3_PATH` and `NVIM_BASE16_THEME`. tmux module sets `focusEvents = true`.
- ONLY inside a devShell (direnv: `use_dev_env <name>` in `.envrc`, e.g. `use_dev_env python`, `use_dev_env "python#py-stable"`; run `direnv allow` after a new/changed `.envrc`): **latex** (texlive scheme-full: latex/latexmk, texlab, zathura, pandoc, tectonic) - vimtex and typst.vim are `cond/enabled = executable(...)` and are not installed/loaded elsewhere; **java** (jdk, gradle, maven, jdtls under `.direnv/tools`, java-debug/test bundles symlinked into `~/.local/share/nvim/nvim-java/packages`); **c-cpp** (clang-tools/clangd, cmake, gdb, gcc/g++); **rust** (fenix toolchain, rust-analyzer, gdb on non-aarch64-darwin); **go** (go, gopls); **node** (typescript-language-server, typescript, prettier); **python** (black, ruff, pyright also global); **typst** (typst, tinymist, typstyle, zathura); **php** (phpactor), **R** (languageserver), haskell (hls, ormolu), shell (shellcheck, shfmt), swift, jupyter. Missing binaries outside devShells = silent skip or one warning. Debuggers lldb/rr/bashdb are provided nowhere (nvim-gdb backend errors outside devShells are expected).
- `lua/config/lsp.lua` enables a server only if `executable(cmd[1])`, so binary names there must match what the devShells provide (`rust-analyzer`, `gopls`, `haskell-language-server-wrapper`, `sourcekit-lsp`, `typescript-language-server`, `phpactor`, ...). Java is special: `has_java = executable("java")` gates nvim-java, spring-boot tools and `vim.lsp.enable("jdtls")` (silent outside the Java devShell).

**Non-nix hosts**: treesitter needs the `tree-sitter` CLI plus a C compiler (`ts.install` of ~12 parsers runs only when `/etc/nixos`/`/etc/nix` are absent; the `:TSUpdate` build hook is skipped on nix); mason was REMOVED (nothing nix-side used it), so non-nix installs get LSP servers only if the user installs binaries by other means; colorscheme falls back to `rand_colorscheme()` when not on nix (`nix_colorscheme()` uses `NVIM_BASE16_THEME`, default base16-catppuccin-mocha); `ts.install`/`nvim-java` jdk auto-install behave differently (`jdk.auto_install = not is_nix_managed`). Other nix hosts may disable the tmux module: never assume tmux; guard with `executable("tmux")`/`$TMUX`.

**Rule about the nix repo**: the audit NEVER edits `~/nix` and never runs `nh os switch`/rebuild. Nix changes are made by the nix owner (the user or a nix-scoped session); the audit only produces precise request lines (package, flake/template, why, which nvim file depends on it). The user rebuilds. `main` of dotfiles and nix is never touched (only on an explicit current-session instruction, restating the action first).

**Platforms and UIs**: NixOS desktop/laptop (primary), macOS (darwin host, nvim via `darwin/services/ext-dotfiles.nix`; gdb excluded on aarch64-darwin, lldb would matter there), a NAS host that runs plain nvim without this config. Terminal: kitty + tmux (allow-passthrough on, focus-events on) + fish; GUI: Neovide (font fixed to `JetBrainsMono Nerd Font` in `ginit.vim`, nvim-qt era `Hack NF` removed). Theme: Catppuccin Mocha everywhere. The user's keyboard has no function/Insert/Page/numpad keys.

**Layout convention (user rule)**: RIGHT = persistent interactive panels (claude-code.nvim at 30% width, aerial outline); LEFT = short single-task panels (`:help` on wide screens, undotree `<Space>u`, `<Space>rr` output terminal).

**Tooling used by the audit harness** (ported into this skill's `scripts/` folder, see `./verification-gates-and-isolated-harness.md`): `scripts/verify.sh <label>` (plugin/keymap/command/autocmd/LSP/option inventories, startup messages, force-load-all errors, filetype smoke test with attach checks, buffer-vs-global shadowing, checkhealth ERROR/WARN with ignore list, startup time ~80-130 ms, smart_comment suite >= 10073 cases, luac syntax, lazy-lock sanity), `scripts/isolated-nvim.sh` (scratch XDG dirs, seeded site/ and nvim-java, restores lock), `scripts/tmux-lib.sh` (real nvim in a private tmux server: send-keys + capture-pane). Always compare an inventory diff: every removed line must map to an approved item.

## 5. LESSONS on process

What wasted time or caused incidents:
- Chunk-parallel EDITING of the guide produced cross-chunk contradictions; the fix was parallel READ-ONLY checkers + ONE single editor (stale removal first, then completeness).
- Sequential sweeps were "too slow"; wide parallel read-only sweeps (30 agents) with a cap of 4 concurrent heavy agents (the laptop once rebooted/crashed) worked. Haiku reports were wrong or gave up on long ranges (always sanity-check counts, give haiku only mechanical work); an agent once reported work it had not done, another reported a false "prompt injection" that was merely the lead's own message.
- /tmp is volatile RAM (wiped on reboot, filled to 99%): anything to keep goes in the project folder or git; assume a crash at any time, so commit + push after every stage.
- Agents that mutate shared state (lazy-lock, clipboard, real git remotes, user tmux sessions) caused real side effects; isolation rules above are mandatory.
- Permission classifier blocks destructive git (`git revert`) for agents: ask the user to run `! git revert ...` instead of working around it.
- `git` can be blocked by the RTK hook in some contexts: use `/run/current-system/sw/bin/git`.
- Headless verification alone gave false greens (vimtex inverse search, vimade-hidden picker letters, resize order, nvim-tree cwd): real-key tests in a private tmux server plus a human check of anything visual are required.
- Decision churn: asking again about decided items wastes the user's time; check `./deliberate-choices-do-not-flag.md` and the git history first.

What worked:
- Per-change gates: after each coding wave run the full verify suite, diff against the previous gate (plugins, keymaps, commands, autocmds, options, LSPs, filetypes, shadowing, lock) and explain every changed line; checkhealth "unexpected" must be 0, startup messages 0, smart_comment >= 10073.
- Stacked PRs + merge commits in order, with an independent reviewer per PR and "Playbook H" (read every hunk of `git diff origin/develop...branch`, map it to a request/decision id, detect reverted decisions with `git log -S`/blame, secret scan) before any PR, merge or "done".
- Batching: one collection pass (bugs vs choices), ONE batch of questions, one coding round, verify-only gate. Obvious bugs are fixed and reported; choices are never decided alone (except under an explicit overnight autonomy rule, recorded with alternatives).
- Manual checks go to the user in batches of 8, quickest first, each step = exact command alone on its line, no trailing punctuation, expectation after each; mismatches become fixes on a branch + a corrected guide row.
- Every change updates the guide (`user-guide/` folder: README with contents + cheat sheet, 10 chapters, 5 language guides), and gets a `desc` on every key of ours; user-guide stale-info removal comes BEFORE adding new content.
- Model split with effort medium: opus for logic/judgement, sonnet for implementation/review/e2e tests, haiku for mechanical checks.
- 101% certainty rule for automated checks: an automated check counts only if it is unambiguous and reproduced (3 retries); otherwise it becomes a manual check for the user. State PASS/FAIL/unsure honestly; never present an unverified claim as verified.
- Secrets/privacy: the repo is public; every diff gets a secret/privacy scan (no emails, private hosts, credentials, store paths in docs that leak identity).
